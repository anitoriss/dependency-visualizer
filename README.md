# Визуализатор графа зависимостей пакетов

Учебный проект по дисциплине «Конфигурационное управление»,
практическая работа №2 (вариант 26).

## 1. Общее описание

`depviz` — консольный инструмент для анализа и визуализации графа
зависимостей пакетов Python (формат pip). Готовые менеджеры пакетов и
библиотеки для получения зависимостей не используются: файл пакета
скачивается из репозитория PyPI, распаковывается и разбирается вручную.
GitHub в качестве источника пакетов не используется.

Реализовано на Python 3.10+ (только стандартная библиотека).

## 2. Описание всех функций и настроек

### Параметры командной строки

| Опция | Описание | По умолчанию |
|---|---|---|
| `-p`, `--package NAME` | Имя анализируемого пакета (обязательно) | — |
| `-r`, `--repo URL\|PATH` | URL репозитория или путь к файлу тестового репозитория | `https://pypi.org/pypi` |
| `-t`, `--test-mode` | Режим работы с тестовым репозиторием | выключен |
| `-v`, `--version VERSION` | Версия пакета | `latest` (последняя) |
| `-o`, `--output FILE` | Имя файла с изображением графа | `graph.svg` |
| `-a`, `--ascii-tree` | Вывод зависимостей в виде ASCII-дерева | выключен |
| `-f`, `--filter TEXT` | Подстрока для фильтрации пакетов | не задана |

### Сбор данных о зависимостях

Используется формат пакетов Python (pip). Менеджеры пакетов, готовые
библиотеки для чтения зависимостей и GitHub не используются — пакет
скачивается и разбирается вручную:

1. **Поиск файла.** Через JSON API репозитория PyPI узнаётся список
   файлов нужной версии:
   - `<repo>/<пакет>/<версия>/json` — заданная версия;
   - `<repo>/<пакет>/json` — последняя версия (если `--version` не
     задан).

   Из ответа берутся только имена и ссылки на файлы. Готовый список
   зависимостей (`info.requires_dist`) **не используется**.
2. **Скачивание.** Выбирается один файл: wheel без привязки к платформе
   (`*-none-any.whl`), иначе самый маленький wheel, иначе архив
   исходников (sdist, `.tar.gz` / `.zip`).
3. **Распаковка.** Архив открывается в памяти модулями `zipfile` /
   `tarfile`, на диск ничего не записывается:
   - wheel — файл `<пакет>-<версия>.dist-info/METADATA`;
   - sdist — файл `PKG-INFO`, а если зависимостей в нём нет (старые
     пакеты) — `<пакет>.egg-info/requires.txt`.
4. **Разбор.** Из `METADATA` / `PKG-INFO` читаются заголовки
   `Requires-Dist:` (формат PEP 508, например `idna (<4,>=2.5)` или
   `tzdata ; sys_platform == "win32"`); секции `requires.txt`
   (`[extra]`, `[:условие]`) переводятся в такие же условия.

Имена пакетов приводятся к каноническому виду (PEP 503): `Jinja2` и
`jinja2`, `zope.interface` и `zope-interface` считаются одним пакетом.

Зависимости с условием `extra == "..."` нужны только для
дополнительных возможностей пакета (`pip install requests[socks]`) и не
учитываются. Зависимости с другими условиями (`python_version`,
`sys_platform`) учитываются всегда, независимо от текущей платформы.

Если в sdist нет ни `Requires-Dist`, ни `requires.txt`, зависимости
задаются только кодом `setup.py`; без его запуска их узнать нельзя, и
список считается пустым.

### Граф зависимостей

Граф строится с учётом транзитивности обходом в ширину (BFS) с явной
очередью, без рекурсии. Для анализируемого пакета берётся версия из
`--version`, для остальных пакетов графа — последняя версия. Каждый
пакет запрашивается у репозитория один раз.

- **Фильтр** (`--filter`): пакеты, имя которых содержит подстроку (без
  учёта регистра), не учитываются — не попадают в граф и не
  анализируются, поэтому их зависимости тоже не попадают в граф (если
  до них нельзя дойти другим путём). Если подстроку содержит сам
  анализируемый пакет, это ошибка.
- **Циклы**: благодаря множеству посещённых пакетов обход не
  зацикливается. После построения графа циклы ищутся обходом в глубину
  с явным стеком и выводятся в виде `A -> B -> C -> A`.

Программа выводит рёбра графа (`пакет -> зависимости`) в порядке обхода,
список исключённых фильтром пакетов и найденные циклы.

### Тестовый режим

С опцией `--test-mode` вместо URL в `--repo` указывается путь к файлу с
описанием графа. Пакеты называются большими латинскими буквами, версий
нет. Формат — по одному пакету в строке:

```
# комментарий
A: B C      # A зависит от B и C
B: C
C:          # у C нет зависимостей
```

Каждый упомянутый пакет должен быть описан своей строкой. Примеры лежат
в `examples/repos/`:

| Файл | Что показывает |
|---|---|
| `simple.txt` | дерево без циклов |
| `diamond.txt` | общая зависимость («ромб») |
| `cycle.txt` | цикл `A -> B -> C -> A` |
| `self_cycle.txt` | пакет зависит сам от себя |
| `complex.txt` | несколько циклов, многобуквенные имена, фильтр |
| `broken.txt` | ошибка: зависимость не описана |
| `bad_name.txt` | ошибка: имя не из больших латинских букв |

### Обработка ошибок

Сообщения об ошибках выводятся в stderr в виде `depviz: ошибка: ...`.
Код завершения 1 — ошибка репозитория (пакет или версия не найдены, нет
соединения, некорректный ответ, ошибка в файле тестового репозитория).
Код 2 — неверный параметр:

- имя пакета пустое или содержит недопустимые символы (в тестовом режиме
  разрешены только большие латинские буквы);
- URL репозитория не начинается с `http://` или `https://`;
- в тестовом режиме не указан или не найден файл репозитория;
- версия пакета некорректна или задана в тестовом режиме;
- файл изображения не имеет расширения `.svg` или его директория не
  существует;
- подстрока фильтра пустая, содержит пробелы или входит в имя
  анализируемого пакета.

## 3. Сборка и запуск тестов

Сборка не требуется. Установка инструментов разработки:

```
pip install -r requirements-dev.txt
```

Запуск:

```
./run.sh [параметры]      (Linux / macOS)
run.bat [параметры]       (Windows)
```

Тесты и проверка стиля:

```
python -m pytest
python -m flake8 src tests
```

## 4. Примеры использования

Реальный репозиторий PyPI, заданная версия:

```
$ ./run.sh -p requests -v 2.31.0

idna -> (нет)
urllib3 -> (нет)
certifi -> (нет)
Циклические зависимости: нет
```

Старая версия, у которой есть только архив исходников (sdist) —
зависимости берутся из `requires.txt`:

```
$ ./run.sh -p flask -v 0.10 -f werkzeug

flask -> jinja2, itsdangerous

markupsafe -> (нет)
Исключены фильтром 'werkzeug': werkzeug

```

Последняя версия с фильтром:

```
$ ./run.sh -p flask -f click
```

Тестовый репозиторий с циклами; фильтр `net` убирает `NET`, а вместе с
ним и `HTTP`, до которого можно дойти только через `NET`:

```
$ ./run.sh -p APP -t -r examples/repos/complex.txt

APP -> CORE, NET, UI

UI -> CORE, THEME

$ ./run.sh -p APP -t -r examples/repos/complex.txt -f net
Граф зависимостей пакета APP (тестовый репозиторий examples/repos/complex.txt): пакетов - 6
APP -> CORE, UI
CORE -> LOG, UTIL
UI -> CORE, THEME
LOG -> (нет)
UTIL -> LOG
THEME -> UI

```

Ошибки:

```
$ ./run.sh -p requests -v 99.0
depviz: ошибка: не найдено в репозитории: https://pypi.org/pypi/requests/99.0/json

$ ./run.sh -p A -t -r examples/repos/broken.txt
depviz: ошибка: зависимость 'X' пакета 'A' не описана

$ ./run.sh -p requests -o graph.png
depviz: ошибка: файл изображения 'graph.png' должен иметь расширение .svg
```

Скрипты для демонстрации лежат в `scripts/` (`*.sh` для Linux/macOS,
`*.bat` для Windows):

- `stage1_params` — параметры и ошибки для каждого из них;
- `stage2_direct` — разные пакеты и версии из PyPI (из wheel и из
  sdist), несуществующие пакет и версия;
- `stage3_graph` — графы тестовых репозиториев (дерево, «ромб», циклы,
  фильтр), ошибки в описании репозитория и графы реальных пакетов.
